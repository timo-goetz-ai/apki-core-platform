## 2. Server vorbereiten
### 2.1 Server-Zugang prüfen
```bash
ssh root@<HETZNER_HOST>
```
Anmelden mit Passwort oder SSH-Key (z. B. aus `~/.ssh/authorized_keys`). Wenn
die Verbindung steht, bist du auf dem Server.
### 2.2 System aktualisieren
```bash
sudo apt update && sudo apt upgrade -y
```
### 2.3 Docker installieren
Falls Docker noch nicht installiert ist:
```bash
# Docker-Repository hinzufügen (Ubuntu)
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/
keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/
docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo
"$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /
dev/null
# Installieren
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin
docker-compose-plugin
# Prüfen
docker --version
docker compose version
```
Unter **Debian** die oﬃzielle Docker-Doku für Debian verwenden.
### 2.4 Firewall
Du nutzt die **Hetzner Cloud Firewall** mit 22, 80, 443 (plus Coolify-Ports). Damit
ist für diesen Stack nichts weiter nötig.
Falls du zusätzlich **UFW auf dem Server** nutzen willst:
```bash
sudo apt install -y ufw
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status
```
### 2.5 Verzeichnis für den Stack anlegen
```bash
sudo mkdir -p /opt/stack
sudo chown $USER:$USER /opt/stack
cd /opt/stack
```
Ab jetzt arbeiten wir in `/opt/stack`.

```bash

```
Beim ersten Mal werden Images gezogen; kann einige Minuten dauern.

```bash
docker compose ps
```
Alle Services sollten „running“ sein. Logs z. B.:
```bash
docker compose logs -f traefik
docker compose logs -f n8n
docker compose logs -f postgres
```
Strg+C beendet die Log-Ausgabe.

## 9. Troubleshooting
### Container starten nicht
```bash
docker compose ps -a
docker compose logs SERVICE_NAME
```
- **postgres:** `init-db.sql` im richtigen Pfad? Keine Syntaxfehler? User/Passwort
wie in `.env`.
- **redis:** `REDIS_PASSWORD` in `.env` gesetzt?
- **n8n:** postgres und redis müssen „healthy“ sein; Logs auf Verbindungsfehler
prüfen.
- **traefik:** Ports 80/443 frei? `sudo ss -tlnp | grep -E ':80|:443'`
### TLS-Zertifikat wird nicht ausgestellt
- Let’s Encrypt braucht von außen erreichbaren Port 80 auf **<HETZNER_HOST>**.
- In Cloudflare: Subdomains n8n, crm, auth, status auf **„DNS only“** (graue
Wolke), Ziel **<HETZNER_HOST>**.
- Traefik-Logs: `docker compose logs traefik` (ACME-Fehler stehen dort).
### 502 Bad Gateway / Service Unavailable
- Backend-Container laufen? `docker compose ps`.
- Nach dem ersten Start 1–2 Minuten warten; Traefik-Service-Ports sind in der
Compose bereits gesetzt.
### n8n: Database / Queue Fehler
- postgres und redis „healthy“; `.env` mit POSTGRES_* und REDIS_PASSWORD
konsistent.
- Nach `.env`-Änderung: `docker compose up -d` erneut ausführen.
### Authentik: Redis/PostgreSQL
- `.env`: REDIS_PASSWORD, POSTGRES_*, DB-Name `authentik`; `init-db.sql` legt
`authentik` an.
### Alle Container neu starten
```bash
cd /opt/stack
docker compose down
docker compose up -d
```

## 10. Backup, Updates, Wartung
### Backup
- **PostgreSQL:** Dumps von main_db, nocodb, authentik (z. B. mit `pg_dump`).
- **Volumes:** postgres_data, n8n_data, nocodb_data, authentik_media,
uptime_kuma_data sichern (z. B. restic/Borg).
- **Optional:** GitHub-Sync mit `GITHUB_REPO` für n8n-Backup.
Beispiel Dump (auf dem Server):
```bash
cd /opt/stack
docker compose exec postgres pg_dump -U admin main_db > backup_main_$
(date +%Y%m%d).sql
```
### Updates
- **Watchtower** im Stack prüft auf neue Images (z. B. täglich). Vorher Backups
haben.
- Manuell: `docker compose pull && docker compose up -d`
### Wartung
- Festplatte: `df -h`, `docker system df`.
- System-Updates: `sudo apt update && sudo apt upgrade -y`.
